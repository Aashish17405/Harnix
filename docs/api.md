# API

Interactive documentation is generated by FastAPI: start the backend and open `http://127.0.0.1:8000/docs` (Swagger UI) or `/openapi.json`. This page is the human summary.

All routes are under `/api`. If `HARNIX_API_TOKEN` is set, every route except `GET /api/health` requires `Authorization: Bearer <token>` (SSE also accepts `?token=` because `EventSource` cannot set headers).

## Errors

Every error uses one shape:

```json
{"error": {"code": "conflict", "message": "Task cannot be started: Invalid task transition running -> running"}}
```

Validation errors (`422`, code `validation_error`) add `details: [{"field": "...", "message": "..."}]`.

| Status | `code` | Meaning |
|---|---|---|
| 401 | `unauthorized` | missing/invalid API token |
| 404 | `not_found` | unknown task/approval |
| 409 | `conflict` / `invalid_transition` | invalid state transition, duplicate run, already-decided approval, report not ready |
| 422 | `validation_error` / `invalid_request` | bad body, repository outside authorized roots, limit above the server limit |
| 429 | `capacity` | `HARNIX_MAX_CONCURRENT_TASKS` already active |
| 503 | `not_configured` | model provider or sandbox unavailable; message contains the fix; the task stays `queued` |

## Endpoints

| Method & path | Purpose |
|---|---|
| `GET /api/health` | Status, version, execution mode, sandbox availability, provider/model and whether it is configured (with the fix if not), `mock_provider`, `auth_required`, `spend` (`{spent_usd}`, an estimate, or `null` when prices are not configured; there is no limit), `graph` (`{enabled, available, detail}`; an unreachable Neo4j never makes the backend unhealthy). Open (no token). |
| `GET /api/graph/status?repo_path=` | Knowledge graph state for one authorized repository: `{enabled, available, detail, repo_id, indexed, graph:{version, complete, files, symbols, imports, calls, indexed_at, notes}, job}`. `503 not_configured` when `HARNIX_GRAPH_ENABLED` is false |
| `POST /api/graph/index` | Body `{"repo_path": "..."}`. Pre-index a repository in the background (`202`, returns the job; poll status). Same call while running returns the running job. `503` if the graph is disabled or Neo4j is unreachable |
| `DELETE /api/graph?repo_path=` | Delete a repository's graph (derived data; rebuilt by the next task or pre-index). Returns `{deleted_nodes}` |
| `GET /api/skills` | Operator skills (`HARNIX_SKILLS_DIRS`): `{items:[{id,name,description,source,listed}], problems, repo_skills}`. Repository skills (opt-in) are discovered per task at run time |
| `GET /api/tasks/{id}/file?path=&version=baseline\|final` | One file as the task started or left it (`{exists, binary, truncated, content}`, secrets redacted; secret-looking/protected paths and escapes are refused with 422) |
| `GET /api/tasks/{id}/images/{n}` | An image attached to the task (n starts at 1); served with its real type, `nosniff`, and a locked-down CSP. `POST /api/tasks` takes `images:[{name, media_type, data}]` (base64): PNG/JPEG/GIF/WebP only, at most `HARNIX_MAX_IMAGES`, each at most `HARNIX_MAX_IMAGE_BYTES`; the type is read from the bytes. Task detail lists `images:[{index,name,media_type,size,width,height}]` (never the bytes) |
| `GET /api/sessions?repo_path=&archived=&limit=&offset=` | This folder's conversations, most recently active first: `{id, title, repo_path, turns, last_status, last_outcome, last_prompt, created_at, updated_at}`; `turns` counts messages that are still part of it |

| `GET /api/knowledge/projects` · `POST /api/knowledge/documents` | the projects you may use with their source counts; hand over one BRD / story / requirement / design / ticket as `text` or an uploaded `data_base64` (`.docx` needs the upload): embeds it, splits a BRD into requirements, creates declared relationships, proposes likely links (returns `ingested`, `suggested`, ...) |
| `GET /api/knowledge/embeddings?project=` · `GET /api/knowledge/chunks/{id}/neighbors?project=&k=` | the project's embedded chunks with 2-D map coordinates (dominant model only), and a chunk's nearest chunks by cosine similarity with the first numbers of its vector |

### `POST /api/tasks` body

```json
{
  "repo_path": "/abs/path/inside/an/authorized/root/repo",
  "instructions": "what to do (required, ≤ 20000 chars)",
  "title": "optional",
  "acceptance_criteria": ["free text, shown to the agent; reported as needing human review"],
  "verification_commands": ["python -m pytest tests/test_x.py"],
  "references": [{"path": "src/app.py", "start_line": 10, "end_line": 20}, {"path": "README.md"}],
  "thinking": "high",
  "skills": ["fix-tests"],
  "max_iterations": 20,
  "max_duration_seconds": 600
}
```

Unknown fields are rejected. `verification_commands` must not contain shell syntax. Limits can only be lowered below the server limits.

`thinking` is `low | medium | high | xhigh` (extra high); omitted means `HARNIX_THINKING_LEVEL`. `skills` (at most 10 ids) are preloaded into the first message; with repository skills off, unknown ids are rejected with `422`. Both are returned on the task and kept by `rerun`.

`references` (at most 10) point the agent at files in the repository: workspace-relative `path`, optional `start_line`/`end_line` (`end_line` needs `start_line`, and must be ≥ it; default is the first 400 lines). They are read **server-side from the task's isolated copy** under the normal path rules, so absolute paths, `..`, links out of the workspace and secret/protected files are skipped, not read. What was attached and what was skipped (with the reason) is recorded in a `task.references` event (`{included:[{path,start,end,truncated}], skipped:[{path,reason}]}`). The content is given to the model as untrusted `<referenced_file>` data. `TaskOut` also returns `references` and `workspace_path` (the isolated copy, used by clients to show per-file diffs); a re-run keeps the references.

### Task fields worth knowing

`status` ∈ `queued | running | awaiting_approval | verifying | completed | failed | cancelled`; `outcome` ∈ `verified | unverified | verification_failed | null`; `provider` is `scripted-mock` for mock runs.

### Report (`task.report`)

`status, outcome, error, provider, execution_mode, agent{finish_reason, claimed_done, final_message}, independent_verification{outcome, blocking, reasons, limitations}, checks{baseline[], final[]}, false_success_claim, changed_files[], project, usage{iterations, model_calls, tool_calls, tool_failures, policy_denials, recovery_attempts, input_tokens, output_tokens, estimated_cost_usd, duration_seconds}, known_limitations[]`. `agent.final_message` is the model's own claim and is not evidence.
